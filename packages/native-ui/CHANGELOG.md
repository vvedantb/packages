# Changelog

## 0.3.14

The brand marks, the `Select` icons and the `Select` options no longer put React Native accessibility props or `testID` on a DOM node on Expo web. The Expo web gallery now loads, and opens and sets a `Select`, with no console error.

- **Fix: brand `Svg` props on web.** On web, `react-native-svg` renders `Svg` as a DOM `<svg>` and passes its props through as they are. React Native Web maps `accessible`, the `accessibility*` props and `testID` on `View` and `Text`, but not on `Svg`. `APP_ICONS` (and the `Icon*` exports) and the `AppMark` tiles set these props on their `Svg`. The Expo web gallery logged React's "does not recognize the `accessibilityElementsHidden` prop on a DOM element" (and the same for `importantForAccessibility`, `accessibilityLabel` and `testID`) and "Received `false` for a non-boolean attribute `accessible`". `AppMark` with `variant="mark"` draws `APP_ICONS`, so it had the same fault. On web a titled mark also had no accessible name, as the unmapped props did nothing there.
  - The new internal `svgA11yProps({ title, testID }, Platform.OS)` in `src/svgA11y.ts` returns the props for each platform. Both components spread it on their `Svg`, so the `Svg` tag sets no accessibility prop of its own. The file has no React Native import, as `toastChrome.ts`.
  - Web, with `title`: `role="img"` and `aria-label={title}`. Without it: `aria-hidden`. `testID` becomes `data-testid`.
  - iOS and Android, with `title`: `accessible`, `accessibilityRole="image"` and `accessibilityLabel={title}`. Without it: `accessible={false}`, `accessibilityElementsHidden` and `importantForAccessibility="no-hide-descendants"`. `testID` is unchanged. The props that only restated the defaults are dropped (`accessibilityElementsHidden={false}` and `importantForAccessibility="auto"` with a title; an undefined role and label without one), so VoiceOver and TalkBack read the marks as before.
  - The `title` and `testID` prop docs on `AppIconProps` and `AppMarkProps` say what web gets.
  - Without `testID`, the result has no test id key. It no longer returns `"data-testid": undefined` on web or `testID: undefined` on iOS and Android.
- **Fix: `Select` icons on web.** `primitives/select.tsx` drew the trigger chevron, the web scroll chevrons and the item check with `lucide-react-native`. A Lucide icon always sets `testID` on its `Svg`, even when it is undefined (`Icon.mjs`, `lucide-react-native` 1.62.0), so the gallery logged "React does not recognize the `testID` prop on a DOM element". They are now the Tabler `IconChevronDown`, `IconChevronUp` and `IconCheck`, which set accessibility props only when given a `title` (`createReactNativeComponent.mjs`, `@tabler/icons-react-native` 3.50.0). None is given one.
  - Same size (16), colours and line (stroke width 2, round caps and joins). The chevron paths match Lucide's. The check is the Tabler check that `Checkbox` draws; its points sit at most 1 unit off Lucide's on the 24-unit grid (0.67 px at 16 px).
  - The internal `Icon` in `primitives/icon.tsx`, which nothing in `src/` renders, now takes a Tabler icon. No file in `src/` imports `lucide-react-native`. It stays in `peerDependencies`, so apps see no change.
- **Fix: `Select` options on web.** `Select` gave each `SelectItem` `accessibilityLabel={option.label}` and `testID` (`${testID}-${value}`, or undefined). On web `@rn-primitives/select` (1.5.2) passes the `Item` props through a `Slot` to the Radix `Select.Item`, a DOM `<div>`, so the gallery logged "React does not recognize the `accessibilityLabel` prop on a DOM element".
  - The new internal `selectItemA11yProps({ label, testID }, Platform.OS)` in `src/selectA11y.ts` returns `aria-label` and `data-testid` on web, and `accessibilityLabel` and `testID` on iOS and Android. Without `testID` it has no test id key. `Select` spreads it on each `SelectItem`, which sets no accessibility prop of its own. The file has no React Native import.
  - On web the option's name is still its text: Radix sets `aria-labelledby` on the option, and that takes precedence over `aria-label`. On iOS and Android the options read as before.
  - The `SelectItem` props type in `primitives/select.tsx` notes that on web they reach a DOM node.
- **Audit.** No other tag in `src/` puts these props on an SVG or another DOM node.
  - The `Toaster` `Svg` sets only its size and viewBox. Its `Pressable` carries the role and hint.
  - The Tabler icons (`Checkbox`, `SearchInput`, `EmptyState`, `Dialog`, `BottomSheetContainer`, `PricingModal`, `Card`, `ListRow`, the `Select` parts and the gallery) take only size, colour and stroke width. Their accessibility sits on the parent `Pressable` or `View`, which React Native Web maps.
  - The internal `Icon` in `primitives/icon.tsx` passes its props to the Tabler icon as they are. A caller that gives it `accessibilityLabel` or `testID` would still reach the DOM on web. No component in `src/` uses it.
  - The `Select` trigger stays a React Native `Pressable` on web: `@rn-primitives/select` renders one when `asChild` is not set, and React Native Web maps its `testID`, `accessibilityRole`, `accessibilityLabel` and `accessibilityState`. The select root, group, content, item indicator and item text and the `Switch` root and thumb are React Native views or text on web too. The Radix viewport and scroll buttons get only `className` and children.
  - Dialogs, alert dialogs and sheets use React Native views. The `Slot` parts in `primitives/overlay.tsx` and `primitives/text.tsx` merge their props onto a React Native child.

- `palette` and `withAlpha`: the web semantic colours (`primary`, `danger`, `success`, `warning`, `default`, `overlay`, `segment` and others) in light and dark, converted from `tokens.css`. `fontClass` lists the Instrument Sans classes.
- `Button`: new variants `default` (same as `primary`), `destructive`, `ghost`, `link` and `tinted`; new sizes `sm`, `default`, `lg` (same as `small`, `medium`, `large`) and `icon`; `startContent` and `endContent`; `children` is optional. It now sets `accessibilityState` (`disabled`, `busy`). Fix: with the default shadow, a caller `style` was dropped; it is now applied after the shadow. A `style` function no longer drops the fill and shadow. With `fullWidth={false}`, the button now sets `self-start`, so it no longer stretches to the width of a column parent (seen on React Native Web). `fullWidth` still defaults to `true`.
- **Visible change from 0.2.x: `Button` colours.** Fill, border and label colours now come from `palette` and `tokens` as styles, not from the app's NativeWind theme, and match the web. `primary` / `default` is near-black with a near-white label (the reverse in dark), `secondary` is neutral grey with a dark label (was a pink label), `outline` is a bordered neutral button (was a pink tint), `ghost` has muted text and `link` primary text. Before, `primary` drew the app's `bg-primary` under a white label, so where an app did not define `primary` the label was white on no fill. The 0.2 pink `outline` is now `variant="tinted"`. Buttons no longer draw the white hairline border. The pill radius, sizes and `primary` shadow are unchanged.
- **Visible change from 0.2.x: fields.** `Input`, `Textarea` and the `Select` trigger have the web field look: white fill (dark: `surface`), a `border`-coloured edge and the field radius (20; the web uses 10), instead of the grey `bg-secondary` pill. Fill, border and text colours are styles from `tokens`, so a `className` colour no longer overrides them; pass `style` instead.
- `Switch`: track and thumb colours come from `palette`, as on the web (checked: `primary`; unchecked: `default` with a `border` edge, a muted tint in dark). Before, the track used `bg-primary` and `bg-input`, which the README does not ask apps to define, so the switch could not be seen on a light background. `onColor` and `offColor` still replace the track fill, and now apply on web too.
- `AlertDialogCancel` now defaults to `outline`, and the `PricingModal` current-plan button is `outline`, as on the web.
- `Card`: new parts `CardHeader`, `CardTitle`, `CardDescription`, `CardContent` and `CardFooter`, and new `description` and `className` props. The `title`, `leftIcon` and `action` props are unchanged.
- `EmptyState`: the props API is unchanged, and `EmptyState.Root`, `.Icon`, `.Title`, `.Description` and `.Actions` compose it as on the web (`default` and `panel` variants).
- `Skeleton` takes `View` props, holds still with Reduce Motion and is hidden from screen readers. `Input`'s default placeholder colour follows the colour scheme (unchanged in light mode).
- New entry `@vvedantb/native-ui/gallery`: `ParityGallery`, a screen that renders the components above for checking on a device. Its button variant rows use `fullWidth={false}`.
- New optional peer `react-native-svg`, for the app marks. Apps that meet the existing peers already have it: `lucide-react-native` and `@tabler/icons-react-native` both require it. No new dependencies; the lockfile is unchanged.
- New `typecheck` script. It checks the package against local declarations of the peers (`types/peers.d.ts`, not published), because the React Native peers are not installed in this repository.
- `tokens.ts` values are unchanged. Its header comment no longer claims that every value matches `tokens.css`; the parity doc lists the differences.
