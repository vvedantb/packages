# Changelog

## 0.3.10

- **Fix: `SearchInput` clear cross invisible on Expo web.** The `IconX` now takes `strokeWidth={1.75}`. Native Tabler reads `stroke` as the colour, so `stroke={1.75}` gave `stroke="1.75"` and no visible line. `tests/searchInput.test.ts` checks the cross takes `color={muted}` and `strokeWidth`, and that no icon in the file sets `stroke`.

## 0.3.9

APIs for V Store: `SearchInput`, a light `/toast` entry, and hidden tabs in `FloatingTabBar`.

- **New: `SearchInput`**, the web `SearchInput` (`search-input.tsx`, with `clear-input.tsx`). A 16 search icon at the start, in the muted colour. While there is text, a clear button at the end: a 14 cross (stroke 1.75), labelled "Clear search" by default, painted at the web 24 (`h-6 w-6` at `right-2`) and brought to a 44 target with its hit slop (`touchSlop`).
  - Sizes come from the new `searchInputSize(size, largerText)` in `src/controlStyles.ts`. `sm` (default) is 32 high, `pl-8`, `text-sm`, icon at 8 (web `h-8 pl-8 text-sm`, `left-2`). `md` is 40 high, `pl-9`, the phone `text-base`, icon at 12 (web `h-10 pl-9`, `left-3`). Both end at `px-3.5`, or `pr-9` while filled. `sm` pads 4 above and below, not the web 8, so the field stays 32 high. Heights are minimums, so Dynamic Type grows the field. With larger text both sizes are the larger `Input`: 64 high, `text-xl` medium, a 24 icon and a 32 clear button.
  - The field has the `Input` look (`fieldStyle`) and the `palette.fieldPlaceholder` placeholder. The font size is a style beside the class, without a line height.
  - Props: controlled `value` and `onChange(text)`; `label` (the accessibility label and default placeholder, default "Search"); `placeholder`; `size`; `onClear`, called after `onChange` whenever the value becomes empty, as on the web; `clearLabel`; `className` for the field; `wrapperClassName`; and the other `TextInput` props. `returnKeyType` is `"search"` (the web `enterKeyHint`). The ref is the `TextInput`.
  - Clearing calls `onChange("")` at once and leaves focus where it was. The web default dissolves the text first; native does not animate it. The clear button is hidden when `editable={false}`.
  - Not ported: the `shortcut` key hint (the web `Kbd`), the `toolbar` variant, `SearchInputConfig` (native has no `UiConfig`) and the dissolve animation.
  - Exported from the root, `/primitives` and the new `@vvedantb/native-ui/search-input`. That entry exports only `SearchInput` and `SearchInputProps` and reaches no optional peer, not even a loader.
- **New entry: `@vvedantb/native-ui/toast`.** It exports `toast`, `Toaster`, `ToastOptions` and `ToastVariant`. It reaches `expo-blur` only through its loader (the toast surface). It does not reach `@gorhom/bottom-sheet`, the date picker, `dayjs`, `expo-router`, `expo-haptics` or `expo-linear-gradient`. The root and `/primitives` still export `toast` and `Toaster`.
  - `Toaster` is unchanged: toasts at the top, inside the safe-area insets, with the success, error, warning and info icons. No trailing alignment was added. The web `SonnerToaster` (`sonner.tsx`) sets no `position` of its own, so there is no web placement to copy.
- **Fix: hidden tabs in `FloatingTabBar`.** A route with Expo Router's `href: null` no longer gets a tab. Nor does a route whose `tabBarItemStyle` resolves to `display: "none"`, because Expo Router's `Tabs` can pass `href: null` on in that form. A route with no descriptor still gets none.
  - The new internal `isTabBarRouteVisible(options)` in `src/tabBarRoutes.ts` decides. Hiding is display-only: focus still compares `state.index` with the route's index among all routes, so visible tabs keep their focus, and a press navigates by route name.
  - The options type moves to `src/tabBarRoutes.ts` and gains `href` and `tabBarItemStyle`. `FloatingTabBarProps` is otherwise unchanged.
  - Apps hide a tab with `options={{ href: null }}` on its `Tabs.Screen` (README).
- **V Store app mark: skipped.** A V Store mark was requested, but `@vvedantb/ui` has no artwork to reuse. Its brand data covers only `projectv`, `vibot`, `vhub`, `vmem`, `verve` and `velth` (`APP_NAMES` and `APP_MARKS` in `src/brand/svg.ts`, and `AppIcons.tsx`); there is no `vstore` glyph. No mark was drawn for native. `APP_NAMES`, `APP_ICONS` and `AppMark` are unchanged, and the brand copies stay byte-identical. A V Store mark needs web artwork first.
- **`expo-linear-gradient` stays optional.** It is still an optional peer (`peerDependenciesMeta`), loaded only by `src/gradient.ts` through its `require` inside `try`. Among the basic entries only `/ambient` reaches it; the new entries do not. A new test in `tests/subpaths.test.ts` checks this.
- `ParityGallery`: the Fields section shows an empty `sm` `SearchInput` (icon and placeholder) and a filled `md` one (with the clear button). The `ScrollView` sets `keyboardShouldPersistTaps="handled"`, so the clear button takes the first tap while the keyboard is up.
- `types/peers.d.ts` declares `IconSearch`.
- Tests:
  - New `tests/searchInput.test.ts` checks `searchInputSize` against the web `search-input.tsx` and `clear-input.tsx` (sizes, icon, clear button, `pr-9`, default labels). It also checks the component's element tree, with React Native stubbed: the icon and no clear button while empty; the labelled clear button and its slop while filled; `onChange("")` then `onClear` on clear; `onClear` when typing empties the field; label, placeholder and ref; `md`; `editable={false}`; and larger text.
  - New `tests/tabBar.test.ts` checks `isTabBarRouteVisible` and the rendered bar: no tab for `href: null`, `display: "none"` or a missing descriptor; focus by the index among all routes; navigation by name with params; a focused hidden route; and a prevented press. With the 0.3.8 check (`!options`) in place, two of these tests fail.
  - `tests/subpaths.test.ts` adds `/search-input` and `/toast` to the V Store list, checks their peers and their exact export lists. `tests/mobile.test.ts` checks the clear button's 44 target and the gallery demos. `tests/exports.test.ts` checks the 0.3.9 version, the new entries and `SearchInput`.

## 0.3.4

Dark-mode contrast fixes from a second look at `ParityGallery` on Expo web, beside the web gallery.

- **Fix: tab colours.** `TabsTrigger` and `PillTabs` take their fill and label colour from the new `tabColors` in `src/controlStyles.ts`, as styles. The colours are the web tab variables (`tabs-pills.css`): an unselected tab has no fill and a `--muted` label; a selected pill is `--default` and a selected segment `--segment`, both with the `--segment-foreground` label (the neutral primary). `soft` is `surfaceSecondary` with a `foreground` label when selected. The segmented `TabsList` track is `--default`. Before, the fills were `bg-surface` and `bg-secondary`, which stay light in dark mode in apps that nest `dark` under those keys. That drew the selected segment as near-white text on white (1.03:1) and unselected labels at about 2.3:1. The selected pill used the pink classes; it is neutral now.
- **Visible change: unselected pills have no fill** (the web pills look). They keep the hairline border. `PillTabs` "Day" / "Week" and `TabsList variant="pills"` look different in light mode. A `className` fill on `TabsTrigger` no longer wins over the tab colours.
- **Fix: tab press feedback.** `TabsTrigger` and `PillTabs` dim with `active:opacity-70` (disabled tabs `opacity-50`). Their `({ pressed }) => style` function was dropped when NativeWind merged it with the class styles, so presses showed no feedback on web.
- **Fix: the `Select` placeholder on web.** Radix `Select.Value` drops `className` and `style`, so the placeholder took the page text colour and font. On web the `SelectValue` primitive now wraps it in a `Text` that carries both, so the placeholder is `palette.fieldPlaceholder`. Native is unchanged (its `Value` is a `Text`).
- **Fix: `Input` and `Textarea` placeholders on iOS and Android.** The input primitive had a native-only `placeholder:text-muted-foreground/50` class. NativeWind turns that class into `placeholderTextColor` and it beats the prop, so the `palette.fieldPlaceholder` set by `Input` and `Textarea` did not apply. Apps that nest `dark` under `muted-foreground` got the light grey at half opacity: near-invisible on a dark field. The class is gone; the primitive defaults `placeholderTextColor` to `palette.fieldPlaceholder` for the scheme. This was found by reading the NativeWind and css-interop source; it has not been checked on a device.
- Ghost `Button` labels were already `tokens.color.muted` (`#a0a0a0` in dark, the web `text-muted-foreground`), measured at 7.7:1 on the dark page. Unchanged.
- Tests: `tests/controlStyles.test.ts` checks `tabColors` against `tabs-pills.css` and the web soft trigger, that tab colours are neutral (not the accent), and label contrast (selected 4.5:1 or more, unselected 4:1 or more, the web's own light value). Source checks: `Tabs` and `PillTabs` use `tabColors` styles, no pink, accent or `bg-secondary` / `bg-surface` fill and no style function; `Input`, `Textarea` and the input primitive pass `palette.fieldPlaceholder`; no component uses a `placeholder:` class; `SelectValue` wraps the web value.
- The entries and subpaths are unchanged. No new dependencies; the lockfile is unchanged.

## 0.3.2

- **Entry points for apps without the heavy optional peers.** The new entries `@vvedantb/native-ui/tab-bar`, `/brand`, `/button`, `/primitives`, `/theme`, `/floating`, `/layout`, `/marketing` and `/ambient` do not import `@gorhom/bottom-sheet`, `@react-native-community/datetimepicker`, `dayjs` or `expo-router`. They load `expo-blur`, `expo-haptics` and `expo-linear-gradient` only through the optional-peer loaders. Between them, they export every name the root entry exports. `BottomSheetContainer` and `DateTimeField` also have their own entries, `/bottom-sheet` and `/date-time`. The README lists what each entry exports.
- The root entry is unchanged for apps that have the peers. It still imports `BottomSheetContainer` and `DateTimeField`, so any import from it resolves `@gorhom/bottom-sheet`, `@react-native-community/datetimepicker` and `dayjs`. Apps without them, such as V Store, should use the new entries.
- **`expo-linear-gradient` is now an optional peer**, loaded with a `require` inside `try`, like `expo-blur`. Without it, `AmbientBackground` draws the solid `tokens.color.background` in place of the gradient.
- `FloatingTabBar` no longer imports `expo-router`. Its props are a local type, `FloatingTabBarProps` (new export), with only the fields the bar reads. The `tabBar` props of Expo Router's `Tabs` on Expo SDK 57 are assignable to it (checked against the `expo-router` 57.0.29 types). `expo-router` stays an optional peer.
- Tests: `tests/subpaths.test.ts` walks the imports from each entry. It fails if a basic entry reaches a heavy peer other than through its loader, or if the entries stop covering the root exports. New tests cover the `expo-linear-gradient` loader and the `AmbientBackground` fallback.
- Known: Expo SDK 58 (`expo-router` 58) passes `emitter` and `navigateToTab` to `tabBar`, not `navigation`. `FloatingTabBar` does not support that yet. An SDK 58 app gets a type error, and at run time a tab press would call `emit` on an undefined `navigation`.
- No new dependencies; the lockfile is unchanged.

## 0.3.1

- **Android glass blur.** With `expo-blur` installed, `FloatingSurface` now blurs on Android as well as iOS. So do `FloatingTabBar`, `Card`, `SettingsSection`, toasts, the `Select` popover and `GlassSheetBackground`. Before, Android always drew the solid fill. The solid fill is now used only when `expo-blur` is not installed, with `blur={false}`, or when Reduce Transparency is on. Web keeps the CSS backdrop blur.
- Android `BlurView` settings: `experimentalBlurMethod="dimezisBlurView"`, plus `blurMethod="dimezisBlurView"` (the name since expo-blur 55), `blurReductionFactor={3}`, and the iOS `tint` (`systemMaterialLight` / `systemMaterialDark`) and `intensity={70}`. The translucent glass fill is laid over the Android blur, because the iOS blur samples that fill and dimezis does not. A factor of 3 blurs harder than the expo-blur default of 4 and keeps the radius (70 / 3, about 23) within the 25 px limit of the RenderScript blur that Dimezis uses below API 29. These values are derived from the expo-blur 58.0.5 source (its Android tint table and radius formula). They have not been checked on a device.
- `GlassBlurProvider` and `GlassBlurTarget` now work; before, they only passed their children through. `GlassBlurTarget` renders an expo-blur `BlurTargetView` (a plain `View` without `expo-blur`), takes `View` props and an `active` prop, and becomes the Android blur target for floating surfaces in the same `GlassBlurProvider`. Since expo-blur 55, Android dimezis blur needs a target. Without one, expo-blur logs a warning and draws only its tint. **Layout change:** `GlassBlurTarget` now adds a view with `flex: 1`. Pass `style` if that does not suit.
- **Optional peers.** `expo-blur` and `expo-haptics` are now optional peers. The package loads them with a `require` inside `try`, which Metro treats as an optional dependency, so `@vvedantb/native-ui` imports and runs without them. Without `expo-haptics`, `selectionHaptic()` does nothing. With it, `FloatingTabBar`, `Tabs` and `Checkbox` presses still fire the selection haptic on iOS and Android.
- New entries: `@vvedantb/native-ui/blur` (`loadBlur`, `glassMode`) and `@vvedantb/native-ui/haptics` (`loadHaptics`, `selectionHaptic`). The `.`, `./gallery` and `./package.json` entries are unchanged.
- Known: from expo-blur 55, each Android `BlurView` logs a deprecation warning for `experimentalBlurMethod` when it mounts. A surface with no target also logs a "no `blurTarget`" warning.
- `types/peers.d.ts`: `BlurView` takes `experimentalBlurMethod`, `blurMethod`, `blurReductionFactor` and `blurTarget`, and `BlurTargetView` and `require` are declared. No new dependencies; the lockfile is unchanged.

## 0.3.0

Parity with `@vvedantb/ui` 0.29.0. The full audit is in `docs/native-ui-parity.md` at the repository root.

- New components with the web names: `Textarea`, `Label`, `Badge`, `Checkbox`, `Separator`, `Progress`, `Spinner`, `CenteredSpinner`, `Avatar` (`AvatarImage`, `AvatarFallback`, plus `initials()`), `StatusDot`, `LabeledSwitchRow`, `Tabs` (`TabsList`, `TabsTrigger`, `TabsContent`; `pills`, `segmented` and `soft` variants).
- Overlays on RN `Modal`, with no new dependency: `Dialog` (`DialogTrigger`, `DialogClose`, `DialogContent`, `DialogHeader`, `DialogTitle`, `DialogDescription`, `DialogBody`, `DialogFooter`), `AlertDialog` (with `AlertDialogAction` and `AlertDialogCancel`), `ConfirmDialog` and `Sheet` (a bottom sheet: `SheetTrigger`, `SheetClose`, `SheetContent`, `SheetHandle`, `SheetHeader`, `SheetTitle`, `SheetDescription`, `SheetBody`, `SheetFooter`). Triggers and closes take `asChild`. Android back closes them; only `AlertDialog` ignores backdrop taps.
- `toast()` and `<Toaster />`: top toasts under the safe area, with the sonner call shape (`toast.success`, `.error`, `.warning`, `.info`, `.loading`, `.dismiss`), replace-by-`id` and one `action`. Mount `<Toaster />` once near the app root.
- Family app marks, ported from `@vvedantb/ui/brand`: `APP_ICONS`, `IconVibot`, `IconVhub`, `IconVmem`, `IconVerve`, `IconVelth`, `IconProjectV`, `AppMark` and `AppWordmark` (Instrument Sans 500, -0.02em). `svg.ts`, `familyApps.ts` and `vProAppBenefits.ts` are byte-identical copies of the web files, so `APP_MARKS`, `APP_NAMES`, `FAMILY_APPS`, `familyApp`, `V_PRO_APP_BENEFITS` and the rest are exported too.
- `UpgradeToProCard` (the web `SidebarUpgradeCard`) and `PricingModal` (the web multi-plan layout as a page sheet, with `onCheckout`).
- `palette` and `withAlpha`: the web semantic colours (`primary`, `danger`, `success`, `warning`, `default`, `overlay`, `segment` and others) in light and dark, converted from `tokens.css`. `fontClass` lists the Instrument Sans classes.
- `Button`: new variants `default` (same as `primary`), `destructive`, `ghost`, `link` and `tinted`; new sizes `sm`, `default`, `lg` (same as `small`, `medium`, `large`) and `icon`; `startContent` and `endContent`; `children` is optional. It now sets `accessibilityState` (`disabled`, `busy`). Fix: with the default shadow, a caller `style` was dropped; it is now applied after the shadow. A `style` function no longer drops the fill and shadow. With `fullWidth={false}`, the button now sets `self-start`, so it no longer stretches to the width of a column parent (seen on React Native Web). `fullWidth` still defaults to `true`.
- **Visible change from 0.2.x: `Button` colours.** Fill, border and label colours now come from `palette` and `tokens` as styles, not from the app's NativeWind theme, and match the web. `primary` / `default` is near-black with a near-white label (the reverse in dark), `secondary` is neutral grey with a dark label (was a pink label), `outline` is a bordered neutral button (was a pink tint), `ghost` has muted text and `link` primary text. Before, `primary` drew the app's `bg-primary` under a white label, so where an app did not define `primary` the label was white on no fill. The 0.2 pink `outline` is now `variant="tinted"`. Buttons no longer draw the white hairline border. The pill radius, sizes and `primary` shadow are unchanged.
- **Visible change from 0.2.x: fields.** `Input`, `Textarea` and the `Select` trigger have the web field look: white fill (dark: `surface`), a `border`-coloured edge and the field radius (20; the web uses 10), instead of the grey `bg-secondary` pill. Fill, border and text colours are styles from `tokens`, so a `className` colour no longer overrides them; pass `style` instead.
- `Switch`: track and thumb colours come from `palette`, as on the web (checked: `primary`; unchecked: `default` with a `border` edge, a muted tint in dark). Before, the track used `bg-primary` and `bg-input`, which the README does not ask apps to define, so the switch could not be seen on a light background. `onColor` and `offColor` still replace the track fill, and now apply on web too.
- `AlertDialogCancel` now defaults to `outline`, and the `PricingModal` current-plan button is `outline`, as on the web.
- `Card`: new parts `CardHeader`, `CardTitle`, `CardDescription`, `CardContent` and `CardFooter`, and new `description` and `className` props. The `title`, `leftIcon` and `action` props are unchanged.
- `EmptyState`: the props API is unchanged, and `EmptyState.Root`, `.Icon`, `.Title`, `.Description` and `.Actions` compose it as on the web (`default` and `panel` variants).
- `Skeleton` takes `View` props, holds still with Reduce Motion and is hidden from screen readers. `Input`'s default placeholder colour follows the colour scheme (unchanged in light mode).
- New entry `@vvedantb/native-ui/gallery`: `ParityGallery`, a screen that renders the components above for checking on a device. Its button variant rows use `fullWidth={false}`.
- New optional peer `react-native-svg`, for the app marks. Apps that meet the existing peers already have it: `lucide-react-native` and `@tabler/icons-react-native` both require it. No new dependencies; the lockfile is unchanged.
- New `typecheck` script. It checks the package against local declarations of the peers (`types/peers.d.ts`, not published), because the React Native peers are not installed in this repository.
- `tokens.ts` values are unchanged. Its header comment no longer claims that every value matches `tokens.css`; the parity doc lists the differences.
