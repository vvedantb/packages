## Noise floor

Chrome does not render the slash menu icons identically between two loads of the same page. Four loads of the original column alone, slash state, light theme, differ from the first by 6, 9 and 6 pixels (measured 18 October 2026). The extracted-against-original result in the slash state varied between 0 and 11 pixels across runs and themes, at one grey level, on icon edges. That is the same noise, not a difference in markup. The other states showed no change on every run.

## What was compared

- **Left (original):** `parity/original/OriginalInputArea.tsx`, a frozen snapshot of the app `InputAreaCore` JSX. The constants and the render from `textareaClassName` onwards are verbatim. Only the data layer (Convex, router, uploads, billing, skills, queue data) is replaced by props. `InputActions`, `ComposerSlashMenu`, `ComposerSlashRow`, `InputBanners`, the compact and slash hooks and the slash item builder are verbatim copies of the app files, except that app brand names in import paths and identifiers are renamed (`@app/shared`, `ConnectionMenuItem`) so the package tree stays free of them.
- **Right (extracted):** `InputArea` from `src/composer`, driven by the same mocked values through its props and slots.
- Each column loads on its own page (`?col=original` or `?col=extracted`) so overlays collide with the viewport the same way.
- States: empty, typing (two lines), slash menu open (`/`), plus menu open, streaming (stop and send), compact (short single line). Each in light and dark.

## What this does not prove

- Both columns use the package primitives (`PromptInput`, `Button`, `InputGroup`, tokens). The app `@vv/ui` wrapper is not in the source tarball, so it is stubbed with the package components (`parity/stubs/vv-ui.tsx`). A difference between the app wrapper and the package would not show here.
- The app strings for `chatComposerClassName`, `getBorderStyles`, `submitButtonStyles` and `bannerStyles` are not in the tarball. `parity/shared.tsx` holds stand-in values that both columns use. The real strings pass through `className`, `borderClassName`, `submitButtonClassName`, `submitIconClassName` and `InputBanners styles`, so they do not change the result here.
- `FadePresence` and `motionFast` are reconstructions. The original column uses the same reconstruction.
- Not covered: attachments, skill chips, queue items, the promo banner, the privacy banner, ghost text, the hover card on slash rows, and the 640 px width only. The app skill picker and brand mark are mocks.
- Ghost text is covered by unit tests only.
- The original column is rendered inside `LazyMotion`, as the app does. `InputArea` brings its own.
